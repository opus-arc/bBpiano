# L2-200c evaluation protocol

The accepted L2-200c/261122 model, D1680 soundboard configuration, embedded
bridge/radiation kernels, hammer noise, duration-dependent key noise and export
gain are frozen. Packaging corrects the remaining C API version label and does
not tune the synthesis model against these evaluation scores.

All measurements use the final obfuscated, stripped, Developer ID-signed arm64
CLI binary. The SHA-256, exact byte count and compiler details are recorded in
the engine and reproducibility JSON files. The distribution ZIP was accepted by
Apple's notary service. Publication of that release is a separate user action.
The executable's deployment target is macOS 27.0, matching this build environment.

## Audio comparisons

The same 22 original MIDI/reference pairs used for L2-Horowitz are retained:
five scales, five chord tests and twelve complete performances. Every input and
reference hash was verified against the historical manifest before rendering.
The CLI's original `-e` path renders full mono float32 WAVs at 88.2 kHz. No
external alignment, gain fitting, EQ, normalization or selected excerpt replaces
the full render. Render durations, peaks, non-finite checks, over-fullscale
sample counts and hashes are recorded per file. Concurrent rendering/scoring
wall times are not standalone CPU performance measurements.

Five float WAVs contain samples above absolute amplitude 1.0: 6,149 samples
across all 22 renders; the maximum absolute sample is 1.6428868. The float files
retain these values. This is an export-level limitation, recorded without
changing the accepted gain or the historical metric preprocessing.

Scale and Polyphony use Pianoteq 9 references; Performance uses the retained
Yamaha Disklavier recordings associated with MAESTRO. The headline statistics
in README and BENCHMARKS summarize only the twelve Performance pairs. Group
means are arithmetic; missing values are never imputed and metrics are never
averaged together.

ViSQOL uses the underlying `VisqolApi`, explicit audio-mode configuration
(`use_speech_scoring=False`), mono 48 kHz input loaded by `librosa.load`, and
Google's `libsvm_nu_svr_model.txt`. This avoids the previously documented wrapper
constructor issue without editing the installed package. The whole-file method
is retained for consistency with the existing tables. It differs from the
short active clips recommended by [ViSQOL's official guidelines](https://github.com/google/visqol#guidelines)
and is not a listener MOS experiment. CLI tail lengths and recorded reference
durations differ; neither file is externally cropped to hide that difference.

CLAP uses `CLAP_Module(enable_fusion=False, device='cpu')`, HTSAT-tiny/Roberta,
the 630k+AudioSet checkpoint, and
`get_audio_embedding_from_filelist([reference, test])`. This retains the
original mono 48 kHz loading and int16 round trip. Python, NumPy and Torch seeds
are fixed at `20261104 + row index`, matching Horowitz. Long files independently
select 10-second crops; this is neither aligned-waveform nor whole-performance
fidelity. Different output durations can change crop locations despite matching
seeds. Historical L0/L1 seeds and environments remain unknown. Cross-version
scores are descriptive and do not establish physical-model accuracy.

Both evaluators must pass identical-input controls. Model hashes and installed
package versions are checked against the Horowitz evaluation. Each metric is
checkpointed independently; source audio and completed scores are retained.

## Engine measurements and binary size

Optimization selection uses 20 separate original `bbpl -t` processes in the
counterbalanced order `-Os, -O3, -O3, -Os`, repeated five times. The same source,
frameworks and compiler are used; optimization level is the only build-option
difference. There is no concurrent synthesis, compilation or metric scoring.
The 88-key mean occupancy is 52.789% for `-Os` and 40.576% for `-O3`, so the
release uses `-O3`. No fast-math option is added.

The final signed binary is then measured in ten independent original `-t`
processes, separately from the optimization comparison. Each range uses the
existing median of five internal measurements, 512 warmup frames, 8,192 measured
frames and 256-frame render blocks at 88.2 kHz. The reported frame time is an
average per sample frame, not maximum audio-device callback latency. Every
run, including any failure, is retained. The new column is added beside the
historical measurements; older versions are not silently rerun or relabeled as
identical test conditions.

Binary size means the uncompressed final signed executable, including its
embedded model data. MB uses 1,000,000 bytes and MiB uses 1,048,576 bytes.
Compressed ZIP size is recorded separately in the release verification.
